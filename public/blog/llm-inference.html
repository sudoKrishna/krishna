The request

One prompt, two kinds of work.

Training learns the weights. Inference uses those weights to produce something a user can consume every time a chat app answers, a coding assistant suggests a line, or an agent picks its next action. The serving system tokenizes input, queues requests, runs the model and streams output back.

Prefill processes prompt tokens in parallel and builds the attention key/value cache. Long prompts add work before the first token. Decode normally produces one new token per sequence per step. Each step depends on the tokens that came before it. For small batches, moving weights and cached data can dominate the step even when the GPU has compute capacity to spare.

During traffic spikes, long prompts and long outputs can delay short requests. Measure time to first token (TTFT) from request start to first streamed token, inter-token latency during streaming, and aggregate output tokens per second. Track p95 alongside averages so slow requests stay visible. Chunked prefill breaks long prefills into pieces that a scheduler can interleave with decode work.

GPU memory

Fitting the weights is step one.

Host RAM serves the CPU and can stage model files or offloaded data. VRAM sits close to the GPU compute and holds active weights, the KV cache and working buffers. Offloading can stretch capacity, but transfers over the host link can add latency.

Weights are shared across requests. A KV cache grows with every active sequence as tokens accumulate. VRAM capacity determines what fits. Memory bandwidth determines how quickly the GPU can read it.

Serving economics

Make each GPU-hour count.

Cost depends on the useful work a fleet completes under its latency target. An API can become cheaper per token as you batch more requests, up until users start waiting too long. Benchmark the prompt and output lengths your product actually sees.

Continuous batching

Fill freed slots as requests finish. Compare throughput and p95 latency at several arrival rates.

Quantize weights

Try fewer bits per weight when memory is tight. Measure quality and kernel speed on your GPU.

Reuse prompt prefixes

Reuse cached KV for repeated token prefixes. Record the hit rate and TTFT gain. New output still needs decode.

Page the KV cache

Allocate KV in blocks as sequences grow. Lower fragmentation can let more requests fit in a batch.

Match model to workload

Try a smaller model for requests it can handle. Measure task quality before routing live traffic.

Right-size capacity

Track queue depth and idle time. Tune replicas and context limits around measured traffic and latency.
